# 언어 참조 정책 — AI가 어느 언어 버전을 읽을지 정하는 규칙

> 🌐 **[Read in English](../en/LANGUAGE-POLICY.md)**

이 파일은 **사람이 아니라 이 프레임워크를 소비하는 AI 에이전트를 위한
설정**이다 — 사람은 그냥 편한 언어를 읽으면 된다. AI가 크리스탈을 읽어야
할 때(예: 새 프로젝트에 이 폴더를 도입하며 원칙을 참고할 때) 한국어
원본(`NN-*.md`)과 영문 번역(`en/NN-*.md`) 중 무엇을 먼저 열지 **매번
새로 판단하지 않도록** 여기 정해둔다.

## 기본값

```
default_reference_language: ko   # SSOT는 항상 한국어 — BLUEPRINT.md 7절 참고
```

이 값을 바꿀 수 있는 건 이 폴더를 가져다 쓰는 프로젝트뿐이다 — 예를 들어
팀의 작업 언어가 영어 중심이면 이 값을 `en`으로 바꿔도 된다. **단, 이
필드를 바꿔도 SSOT 자체(어느 파일을 실제로 고치는가)는 안 바뀐다** — 이건
"읽기 우선순위" 설정이지 "쓰기 대상" 설정이 아니다(BLUEPRINT.md 7절의
SSOT 원칙과 절대 혼동하지 않는다).

## AI가 실제로 따르는 결정 순서 — 티어와 예외

읽어야 할 크리스탈이 정해지면, 아래 순서대로 판단한다 — 앞 조건이
뒤 조건보다 항상 우선한다:

| 순서 | 조건 | 행동 |
|---|---|---|
| 0 (항상 최우선) | 해당 크리스탈의 `en/` 번역 파일이 아예 없다 | 무조건 한국어 원본을 읽는다 — 선택지가 없다 |
| 0 (항상 최우선) | `en/` 번역 파일은 있지만 번역 동기화 감지(`agent-ops-framework-translation-sync-check.py`, BLUEPRINT.md 7절)가 STALE로 표시했다 | 무조건 한국어 원본(SSOT)을 읽는다 — 낡은 번역은 잘못된 근거가 될 수 있다 |
| 0 (항상 최우선) | 같은 감지 스크립트가 DIVERGED로 표시했다(번역이 스탬프 갱신 없이 직접 수정됨 — 예: 영문 기여자의 PR) | 한국어 원본을 기본으로 읽되, **영문 쪽에 아직 SSOT로 반영 안 된 최신 기여가 있을 수 있다는 걸 명시적으로 인지한다** — 정확성이 중요한 판단이면 영문도 함께 열어 무엇이 다른지 비교한다. 이 상태를 발견하면 BLUEPRINT.md 7절의 조율 절차(SSOT로 반영 후 재번역)를 사람에게 알린다 |
| 1 (기본값) | 위 예외에 안 걸린다 | `default_reference_language`가 가리키는 언어를 읽는다(기본은 한국어) |
| 2 (효율 예외) | 지금 작업 중인 프로젝트/세션의 주 언어가 영어이고, `default_reference_language`가 아직 `ko`로 남아있어도 | 번역이 최신 상태라면 영문을 먼저 읽어도 된다 — 매번 한국어를 영어로 속으로 번역해가며 읽는 비용을 아낄 수 있다. **단**: 그대로 인용하거나 정확한 수치·URL·arXiv ID를 옮겨 쓸 때는 한국어 원본(SSOT)과 대조해 확인한다 — 번역 과정에서 숫자·고유명사가 틀릴 위험은 항상 있다 |

## 이 정책 자체가 흔들리면 안 되는 것

- **정확성이 걸린 인용(수치, URL, 논문 ID, 코드 식별자)은 언어 선택과
  무관하게 항상 SSOT(한국어)로 최종 대조한다** — 티어 2(효율 예외)는
  "먼저 무엇을 읽어도 되는가"에 관한 것이지 "무엇을 믿어도 되는가"에
  관한 게 아니다.
- 이 파일 자신도 [BLUEPRINT.md](BLUEPRINT.md) 7절과 마찬가지로 도메인
  지식이 없는 설정 파일이라 새 프로젝트로 그대로 복사해도 안전하다 —
  단, `default_reference_language` 값은 그 프로젝트의 실제 필요에 맞게
  다시 판단해서 채운다.
