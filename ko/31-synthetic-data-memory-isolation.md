# 합성 데이터 ↔ 영구 기억 격리 — 평가용 가짜 입력이 진짜 이력으로 둔갑하는 사고

> 🌐 **[Read in English](../en/31-synthetic-data-memory-isolation.md)**

**버전**: 1.0.3
**콘텐츠 해시**: sha256:1bbabfd0b56f (본문 기준, 이 두 줄 제외)

**검증 강도**: 🟡 원본 프로젝트의 실제 사고 사례에서 패턴만 일반화. 소프트웨어
공학의 "테스트/운영 데이터 분리" 일반 원칙과 같은 계보이지만, 이 문서
자체가 그 일반 문헌을 원문 대조하지는 않았다.

## 문제

에이전트가 (a) 스킬을 실제로 실행해보는 평가(eval) 하네스와, (b) 사용자와의
실제 상호작용을 누적하는 영구 기억 파일(선호·이력 로그)을 **둘 다** 갖고
있으면, 구조적으로 이 사고가 발생할 수 있다: 평가 하네스가 "사용자인 척"
합성 시나리오를 스킬에 입력하고, 그 스킬이 정상 동작대로 "새로 드러난
사실을 영구 기억에 기록"하는 절차를 그대로 수행하면서, **합성 입력이 실제
사용자 이력과 구분 없이 저장**된다. 평가를 여러 번 반복하면 있지도 않은
사건이 반복적으로 "일어난 것처럼" 누적된다 — 사실이 아닌 걸 저장했다는
것보다, **저장된 것이 사실인지 합성인지 구분할 방법이 없어진다**는 게
더 근본적인 문제다.

## 왜 이것이 별개의 축인가

패턴 매칭 가능한 비밀값(API 키, 이메일)이 새는 걸 막는 가드레일([07-
prompt-guardrails/](07-prompt-guardrails/))과도, 프로젝트 전체 단위의
기밀 정보를 막는 가드([23-confidential-project-protection.md](23-confidential-project-protection.md))와도 다르다 — 여기서 새는 건 비밀이
아니라 **출처가 오염된 사실 그 자체**다. 정규식으로 못 잡는다 — 평가
하네스가 만든 문장은 형식상 실제 사용자가 말한 문장과 동일하게 생겼다.

## 대응 원칙

1. **평가 실행임을 구조적으로 표시한다** — 프롬프트에 "이건 테스트다"라고
   적어두는 것만으로는 부족하다(자연어 지시는 누락·무시될 수 있다).
   가능하면 평가 실행 경로 자체가 영구 기억 파일에 쓰기 권한이 없도록
   막거나, 별도의 격리된 경로(테스트 전용 사본)에만 쓰도록 하네스를
   설계한다.
2. **쓰기 전 경로 검사**: 스킬이 "맥락 업데이트" 단계에서 실제 운영
   경로에 쓰기 직전, 지금 실행이 평가 하네스로부터 왔는지 확인하는
   단계를 둔다 — 이 검사가 없으면 스킬 자신은 평가 실행과 실제 실행을
   구분할 방법이 없다.
3. **발견 시 삭제가 아니라 정정 주석**: 이미 오염된 기록을 발견하면 조용히
   지우지 않는다 — "이 항목은 YYYY-MM-DD 검토 결과 평가 실행 중 합성
   입력으로 밝혀져 정정됨"이라고 남긴다. 조용히 지우면 감사 이력(누가
   언제 무엇을 왜 고쳤는지)이 끊긴다 — [12-blameless-postmortem-
   template.md](12-blameless-postmortem-template.md)의 "숨기지 않고
   기록한다" 원칙과 같다.
4. **주기적 교차검증**: 영구 기억 파일에 "정말 실제 상호작용에서만
   나올 법한 구체성(정확한 날짜, 사용자만 알 수 있는 세부)"이 있는지
   가끔 훑어본다 — 평가 하네스가 만든 문장은 보통 더 일반적이거나
   템플릿 티가 나는 경우가 많아 완전 자동화는 어렵지만 사람의 눈으로는
   비교적 잘 걸린다.

## 이 문제가 발생하는 정확한 조건 (과잉 적용 방지)

아래 두 조건이 **모두** 있어야 이 위험이 실제로 성립한다 — 하나만
있으면 해당 없다:
- 에이전트가 스킬을 종단간(end-to-end) 실행하는 평가/테스트 하네스를
  갖고 있다(단순 유닛 테스트로 함수 하나만 검증하는 구조는 해당 없음).
- 그 스킬의 정상 동작 자체가 "실행 중 드러난 사실을 영구 기억 파일에
  쓴다"는 부작용을 포함한다(순수 함수처럼 입력→출력만 하고 아무 상태도
  안 남기는 스킬은 해당 없음).
