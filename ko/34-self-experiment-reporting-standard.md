# 자가 실험 보고 표준 — 정성·정량·신뢰도 3요소 + 사전예측·과정추적

**콘텐츠 해시**: sha256:cac45f60e0e5 (본문 기준, 이 두 줄 제외)

**검증 강도**: 🟡 표본 크기 판단 원칙(포화 곡선)은 Self-Consistency(Wang et
al. 2022, [arXiv:2203.11171](https://arxiv.org/abs/2203.11171)) 원문 확인 —
🟢. 5단계 신뢰도 마커 체계 자체는 이 프레임워크의 자체 설계이지 외부
표준(예: 의학 연구의 GRADE 근거등급 체계)을 직접 대조한 건 아니다 —
과장하지 않기 위해 🟡로 구분해 표시한다.

에이전트가 자기 자신의 어떤 기법·편향·가설을 검증하려고 **비정형·1회성
실험**(정해진 케이스·루브릭이 있는 회귀 평가가 아니라, "이게 진짜인지
궁금해서 직접 해본" 종류)을 돌릴 때, 그 결과를 어떻게 보고해야 신뢰할
수 있는지를 다룬다.

## 이것이 04·18과 다른 지점 (G3)

[04-eval-engineering-methodology.md](04-eval-engineering-methodology.md)는
**정해진 케이스·루브릭으로 산출물을 회귀 검증**하는 파이프라인이고,
[18-determinism-and-reproducibility.md](18-determinism-and-reproducibility.md)는
**왜 같은 입력에 답이 달라지는지**의 근본 원인을 다룬다. 이 크리스탈은
그 둘 중 무엇도 아니다 — 정해진 케이스가 없는, 에이전트가 스스로 만든
가설을 스스로 검증하는 **자가 실험**을 어떻게 정직하게 보고하는가다.
셋 다 "신뢰할 수 있는 근거"를 다루지만 적용 지점이 다르다: 04는 산출물
품질, 18은 비결정성의 원인, 이 크리스탈은 임시 실험의 보고 형식.

## 필수 3요소 — 전부 있어야 "실험"으로 인정한다

### 1. 정성적 서술
무엇을 관찰했고 왜 중요한지, 숫자가 실제로 무엇을 뜻하는지를 산문으로
설명한다. 숫자만 나열하고 끝내지 않는다.

### 2. 정량적 지표
관찰을 실제 숫자(표본 크기 n, 비율/카운트, 가능하면 신뢰구간)로 표현한다
— 실제 계산 도구로 셈하고 손으로 어림잡지 않는다.

**표본 크기(n)를 정하는 원칙 — 포화 곡선을 직접 관찰한다**: Self-
Consistency 논문이 실측한 "경로 수를 5→10→40으로 늘릴수록 개선폭이
줄어들다가 어느 지점부터 거의 평평해진다"는 포화 패턴을 표본 크기
설계의 참고 원칙으로 쓴다 — 임의로 n을 고정하는 대신, n을 하나씩
늘려가며 "판정이 더 이상 안 바뀌는 지점"을 직접 찾는다. **강제 규칙은
아니다** — 단발 이분법 확인(되는지/안 되는지)엔 과한 기준이고, 다단계·
비교 실험(A vs B 효과 크기 비교)에만 권고한다.

### 3. 신뢰도 평가 — 결과와 별도 축으로, 반드시 명시한다

| 마커 | 뜻 | 기준 |
|---|---|---|
| 🟢 높음 | 여러 독립 반복 + 충분한 표본 + 통제된 설계(혼입변수 배제) | 대체로 n이 크거나 반복 실험이 일관된 방향을 보일 때 |
| 🟡 중간 | 반복은 있으나 표본이 작거나 통제가 불완전 | |
| 🟠 낮음 | 단일 시도, 또는 알려진 방법론적 결함(천장효과 등) 있음 | |
| ⚪ 미평가 | 아직 신뢰도 판단을 안 함(정직하게 비워둠, 지어내지 않음) | |
| 해당없음(예외) | 정성적 관찰만 의도된 실험(정량화가 원천적으로 부적절) | 드물어야 함 — 남발 금지 |

**핵심 원칙**: "효과가 있다/없다"(결과)와 "이 결과를 얼마나 믿어도
되나"(신뢰도)는 다른 축이다. null 결과라도 잘 설계된 큰 표본이면 신뢰도가
높을 수 있고, 강한 효과라도 n=1·통제 안 된 관찰이면 신뢰도가 낮다 —
결과의 강도와 신뢰도를 섞어서 말하지 않는다.

## 확장 2요소 — 다단계·설계 변경이 있는 실험에만

### 4. 사전 예측
실행 **전에** 가설과 예상 결과를 먼저 적는다. 실제 결과가 나온 뒤
사후적으로 "그럴 줄 알았다"는 서사를 쓰지 않기 위한 절차 — 예측이
틀렸어도 그대로 남긴다(맞았을 때만 골라 남기면 이 절차 자체가
무의미해진다). 단발 관찰성 실험은 생략 가능하다.

### 5. 과정 추적 (사고→행동→관찰)
조사·실험이 여러 단계를 거치며 중간 관찰이 다음 단계를 바꿨다면(1차
결과가 이상해서 원본을 다시 열어봤다, 설계 결함을 발견해 재설계했다)
그 흐름을 순서대로 짧게 남긴다 — 최종 결론만 쓰면 "왜 이렇게 설계가
바뀌었는지"가 사라진다. 처음 설계 그대로 끝난 단순 실험은 생략 가능하다.

## 신뢰도가 낮게 나올 수밖에 없을 때

표본이 근본적으로 제한된 상황(예: 하루 세션 동안 실제 발생한 이벤트로만
표본이 한정됨)이면, 신뢰도를 인위적으로 올리려 하지 않는다 — 낮다고
정직하게 쓰고, "신뢰도를 어떻게 높일 수 있는가"를 다음 실험 후보로
남긴다. 표본이 작다고 실험 자체를 안 하는 것보다, 작은 표본임을 정직하게
표시하고 실행하는 게 낫다 — 표시 없이 과장하는 것만 피하면 된다.
