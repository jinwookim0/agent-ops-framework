# 모듈 포맷 — 기능 하나를 다른 프로젝트로 즉시 떼어 쓰기

> 🌐 **[Read in English](../en/08-module-format.md)**

**버전**: 1.0.4
**콘텐츠 해시**: sha256:8bbe112c2609 (본문 기준, 이 두 줄 제외)

**검증 강도**: 🟢 npm 등 패키지 매니저의 매니페스트 개념을 소규모로
재현했고, 원본 프로젝트에서 여러 실제 모듈이 이 포맷으로 이식·검증됨.

프로젝트 안의 개별 기능(스킬/에이전트 단위)은 대개 **그 프로젝트에 강하게
결합**돼 있다 — 공유 컨텍스트 파일, 거버넌스 문서, 때로는 다른 기능을
암묵적으로 전제한다. 그래서 실행 파일 하나만 복사해서 다른 프로젝트에 넣으면
참조가 깨지거나(파일이 없음) 조용히 성능이 떨어진다(맥락 없이 동작). 이
문서는 그 문제를 푸는 **패키징 규약**이다.

## 왜 원본과 별도 위치에 두는가

원본은 **프로젝트 안에서 실행되는 진짜**다(공유 컨텍스트 파일 등을 실제로
참조하며 실행됨). 모듈은 그 원본에서 **프로젝트 의존성을 제거하거나
명시적으로 선언한 배포용 사본**이다 — 원본과 별개로 관리한다(원본을 고치면
모듈도 수동으로 동기화, 자동 동기화 장치가 없다면 정직하게 그렇게 밝힌다).

## 모듈 구조

```
modules/<skill-name>/
├── MODULE.md      # 매니페스트 — 아래 형식
├── SKILL.md        # 이 프로젝트 의존성을 제거/대체한 버전
├── README.md        # 사람이 읽는 설치·사용 안내
└── (선택) 번들 참고자료  # 원본이 참조하던 문서 중 필요한 부분만 발췌
```

## MODULE.md 형식

```markdown
---
name: <기능 이름>
version: 1.0.0
source: <원본 프로젝트>, <원본 경로>, <내보낸 날짜>
verified: <원본이 평가(eval)로 공식 검증됐는지, 언제, 결과>
dependencies: none | <목록>
---

## 이것은 무엇인가
(한 줄 설명 + 왜 유용한지)

## 설치
이 폴더의 실행 파일(및 있으면 번들 참고자료)을 대상 프로젝트의 해당
위치로 복사한다. 그게 전부다 — 추가 설정 없음.

## 의존성 (정직하게)
- 없음: 완전히 독립적으로 동작
- 있음: 대상 프로젝트에 <파일/구조>가 없으면 <구체적으로 뭐가 저하되는지>
  (예: "이력 기반 개인화가 빠지고 매번 처음부터 조언한다" — 크래시하지 않고
  성능만 저하되는 게 원칙, 아래 "우아한 성능저하" 참고)

## 검증 상태
원본이 이 프로젝트에서 공식 검증된 이력을 그대로 밝힌다 — 모듈로 뗀 뒤
재검증한 건 아니므로 "이 버전도 100% 보장"이라고 과장하지 않는다.
```

## 원칙

1. **우아한 성능저하(graceful degradation)**: 원본 프로젝트 전용 파일이
   대상 프로젝트에 없어도 기능이 죽거나 에러를 내지 않는다 — 있으면
   활용하고 없으면 "이번엔 이력 없이 진행"으로 자연스럽게 넘어가도록
   문구를 조정한다.
2. **번들 vs 참조 분리**: 원본이 참고하던 프로젝트 문서 중, 그 기능의
   핵심 동작에 실제로 필요한 부분만 발췌해 모듈 폴더에 함께 넣는다.
   프로젝트 전체 거버넌스 문서(안전 가드레일 전체 등)를 통째로 복사하지
   않는다 — 필요한 원칙만 실행 파일 안에 직접 풀어 쓰거나, 짧은 발췌
   파일로 넣는다.
3. **버전은 스냅샷이다**: 모듈은 내보낸 시점의 스냅샷이다 — 원본이 이후
   개선되면 모듈은 자동으로 안 따라간다. 필요하면 다시 요청해서 재수출한다
   (자동 동기화는 이 규약의 범위 밖).
4. **검증 표시는 정직하게**: MODULE.md의 "verified" 필드는 **원본**이
   통과한 기록이지, 모듈로 뗀 버전을 다시 검증한 게 아니다 — 이 구분을
   흐리지 않는다.

## 이 크리스탈 모음 자체에도 같은 원칙이 적용된다

`agent-ops-framework/` 자체가 이 규약의 더 큰 스케일 버전이다 — 개별 기능
하나가 아니라 프로젝트 전체의 운영 방식을 떼어낸 것. 3번(버전은 스냅샷),
4번(검증 표시는 정직하게) 원칙을 이 폴더 전체에도 그대로 적용한다 — 원본
문서가 실전에서 거쳐온 검증 이력을 요약하되, 이 크리스탈 버전 자체를
독립적으로 재검증한 건 아니라고 각 파일에 명시한다.
