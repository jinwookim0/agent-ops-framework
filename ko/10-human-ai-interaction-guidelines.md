# 사람-AI 상호작용 18원칙 — Microsoft Research 표준 적용 체크리스트

> 🌐 **[Read in English](../en/10-human-ai-interaction-guidelines.md)**

**버전**: 1.0.2
**콘텐츠 해시**: sha256:ff18bc969ee2 (본문 기준, 이 두 줄 제외)

이 크리스탈은 **어느 한 프로젝트의 실전 역사가 아니라 외부 글로벌 표준을
원천으로** 한다 — 아래 10~20번대 크리스탈 전체가 같은 방식이다: 어느
한 프로젝트에도 국한되지 않는 검증된 표준을 1차 자료로 직접 확인해
가져온다.

## 근거 (1차 자료 확인)

🟢 Amershi et al. 2019, *Guidelines for Human-AI Interaction* (Microsoft
Research, CHI 2019, [공식 논문 페이지](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)) —
HAX Design Library([microsoft.com/en-us/haxtoolkit](https://www.microsoft.com/en-us/haxtoolkit/))에서
18개 가이드라인 원문을 직접 확인. AI 제품군(챗봇·추천시스템·
LLM 기반 어시스턴트 등)에 범용 적용 가능하도록 설계됐고, CHI 2019 이후
업계에서 널리 인용되는 표준 체크리스트다.

## 18개 가이드라인 (G1~G18)

| # | 가이드라인 | AI 에이전트 프로젝트에서의 의미 |
|---|---|---|
| G1 | 시스템이 할 수 있는 것을 명확히 한다 | 에이전트의 실제 도구/권한 범위를 사용자가 알 수 있게 문서화한다(예: "이 작업은 실제 발송을 못 한다, 초안만 만든다") |
| G2 | 시스템이 그걸 얼마나 잘 하는지 명확히 한다 | 확신도 등급 표기(`confidence_gate`류) — 산출물마다 얼마나 신뢰할 수 있는지 표시 |
| G3 | 맥락에 맞게 서비스 시점을 조절한다 | 사용자가 원하지 않을 때(예: 집중 작업 중) 자동 알림·개입을 자제한다 |
| G4 | 맥락에 관련된 정보만 보여준다 | 산출물에 무관한 정보를 채워넣지 않는다 — 관련성 없는 데이터로 신뢰도를 과시하지 않는다 |
| G5 | 관련 사회적 규범에 맞춘다 | 어투·형식이 그 도메인의 관례(전문 조언 면책 문구 등)를 따른다 |
| G6 | 사회적 편향을 완화한다 | 산출물이 특정 집단에 대한 근거 없는 가정을 담지 않는지 점검한다 |
| G7 | 효율적인 호출을 지원한다 | 자주 쓰는 작업은 최소한의 입력으로 실행 가능하게 한다 |
| G8 | 효율적인 취소를 지원한다 | 진행 중인 작업을 쉽게 중단할 수 있게 한다 — 특히 비가역적 행동 전 단계에서 |
| G9 | 효율적인 정정을 지원한다 | 사용자가 AI의 결과를 쉽게 고칠 수 있는 구조를 둔다(전체 재실행이 아니라 부분 수정) |
| G10 | 불확실할 땐 서비스 범위를 좁힌다 | 애매한 경우 광범위하게 추측하지 않고, 확실한 부분만 답하거나 명시적으로 되묻는다 |
| G11 | 시스템이 왜 그렇게 했는지 명확히 한다 | 판단 근거(어떤 도구를 왜 썼는지, 어떤 자료를 참고했는지)를 결과와 함께 남긴다 |
| G12 | 최근 상호작용을 기억한다 | 같은 세션/대화 내 이전 지시와 모순되게 행동하지 않는다 |
| G13 | 사용자 행동에서 학습한다 | 반복될수록 사용자의 선호·패턴이 누적되는 구조를 둔다 |
| G14 | 신중하게 업데이트·적응한다 | 학습된 선호를 성급하게 일반화해 적용하지 않는다(한두 번의 신호로 전체 정책을 바꾸지 않는다) |
| G15 | 세분화된 피드백을 유도한다 | "좋아요/싫어요"보다 구체적으로 무엇이 왜 안 맞았는지 물을 수 있게 한다 |
| G16 | 사용자 행동의 결과를 알려준다 | 비가역적 행동을 실행하기 전, 그 결과가 무엇인지 명확히 전달한다 |
| G17 | 전역 제어를 제공한다 | 시스템 전체 설정(자동 실행 끄기, 알림 빈도 조절 등)을 사용자가 조정할 수 있게 한다 |
| G18 | 변경 사항을 사용자에게 알린다 | 시스템 동작이 바뀌면(새 규칙 추가, 자동화 범위 확장 등) 그 사실을 알린다 |

| G11 | [03-epistemic-immunity-catalog.md](03-epistemic-immunity-catalog.md) 8번(툴 실행 미확인 주장 방지) |

| G17 | [07-prompt-guardrails/](07-prompt-guardrails/)가 안전장치를 프로젝트 설정으로 노출하는 것과 같은 정신 |

이 대응표 자체가 흥미로운 발견이다 — 원본 프로젝트가 자체적으로(외부 표준을 몰랐던
시점에) 실전에서 발전시킨 원칙들이, 이미 존재하는 글로벌 HCI 표준의
일부와 상당 부분 겹친다. 이건 "레포가 이 표준을 베꼈다"가 아니라 "실제
사용자 불만·사고를 반복해서 겪으며 독립적으로 비슷한 결론에 도달했다"는
뜻이고, 그 자체가 이 표준의 타당성을 보강하는 증거로 읽을 수 있다(단,
이건 이 대응표 작성 과정에서의 관찰이지 통계적으로 검증된 주장은 아니다 — 과잉해석하지
않는다).

## 프로젝트에 도입하는 법

18개를 한 번에 다 적용하려 하지 않는다. **작업 실행 후 자가점검 체크리스트로
쓰는 걸 권한다**: 산출물/기능을 만들 때마다 "이 18개 중 이 산출물과 관련
있는 게 어느 것인가"를 먼저 추리고(전부 해당하지 않는다 — 예: 정보 조회형
산출물엔 G7~G9의 취소·정정 개념이 약하게만 적용됨), 관련 있는 항목만
구체적으로 점검한다. 매번 18개 전체를 억지로 채우려 하면 형식적 체크박스가
된다.
